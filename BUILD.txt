Splice input verification on Neutrino
------------------------------------
The native build applies patches/lnd-neutrino-splice.patch. Peer splice inputs are located through compact filters and verified blocks, then checked for spends from their creation height through the current tip. No explorer or trusted gettxout service is used. Unknown, spent, mismatched, reorged, or timed-out inputs fail closed. The channel negotiation retains its existing ten-second input-check budget and cancels unfinished scans. Splicing still requires protocol.splice=true on the node profile; enabling it changes channel database compatibility and must be retained for that profile.

The same patch reports confirmations for published splice transactions from the splice chain notifier (including intermediate progress and historical discovery after restart) when using Neutrino, retaining gettxout reporting for full-node backends. The phone displays pending local/remote liquidity changes and the native lock target; channel labels use the original funding outpoint so a completed splice does not lose them.

2026-11-12 splice counter correction: shared funding transactions can stay unconfirmed in the wallet transaction store after mining. Neutrino status now uses a bounded, read-only chain-notifier inclusion lookup and the current chain height, independently of peer reconnection. The lock-depth policy is unchanged. Regression coverage includes historical inclusion, advancing blocks, reorg notifications, and a bounded unconfirmed lookup.
